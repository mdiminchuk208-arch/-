# Market microstructure audit — prospective readiness

**Verdict: STOP for metadata readiness and OOS registration.** The proposed capture and epoch protocol handles the present failure conservatively, but there is no verified production `priceFilter.tickSize` for BTCUSDT or ETHUSDT in this gate. I reviewed `CURRENT_METADATA_CAPTURE.json`, `PROSPECTIVE_TICK_EPOCH_PROTOCOL.json`, the `selected_instrument` and `prospective_observation` functions in `scripts/machine_strategy_v3_prospective_integrity.py`, their raw receipts, and the applicable frozen validation/execution contracts. I did not inspect strategy outcomes or run financial code.

Both exact-symbol unauthenticated Bybit V5 `category=linear` instrument requests returned HTTP 403. The raw 96-byte CloudFront country-block responses each hash to the recorded SHA-256 `7ef856c945703d5772f1b1f2a8c65913247c9b0769302b10facfe14fa1e2083c`. I independently rehashed all 14 response bodies listed in `CURRENT_METADATA_CAPTURE.json`; each matched its receipt and inventory hash and status. A successful official notice retrieval is separate from a successful production instrument response. The notices cannot establish the present filter or bridge earlier unknown intervals. The current artifact correctly reports `verified=false`, `epoch_opened=false`, empty `current_tick_epochs`, and STOP for each symbol.

`selected_instrument` checks HTTP 200 plus exchange `retCode=0`, `result.category=linear`, a unique row, exact BTCUSDT/ETHUSDT symbol, `LinearPerpetual`, USDT quote and settle, `Trading`, and a finite positive exact-decimal string at `priceFilter.tickSize`. It retains the full `priceFilter` and labels proof as point-in-time only. These checks correctly target Bybit's executable order-price increment. `priceScale`, chart decimals, kline OHLC precision, instrument documentation examples, and another contract category are not substitutes. The filter does not establish dynamic price-band acceptance or order fills.

`prospective_observation` checks request/response order, uses completed response receipt as `known_at`, and refuses to open a continuous epoch from a point observation. The JSON protocol explicitly makes all between-capture intervals UNVERIFIED, including equal adjacent captures, and requires separate per-decision causal production validation before any later candidate decision. A changed setting needs a post-effective official applied capture. This is the right conservative treatment: a later snapshot cannot locate an unobserved change inside a polling gap, and a notice's advertised effective time is not proof of deployment. The optional `effective_at` argument must mean an already applicable, independently supported boundary; an advance notice with a future effective time should remain a separate notice record until application is confirmed. Keep issuer publication claim, first observed notice capture, advertised effective time, server Date, request start and validated response completion distinct.

For a future control gate, the minimum forward proof is: immutable official production raw response and validation for each exact instrument; independently retained dated notice observations; a defined freshness and failure rule at every frozen decision/order event; and an UNKNOWN/WAIT interval on missed capture, contradictory notice or observed change. A response completed after an M15 open or H1 decision cannot authorize that earlier event. If a filter changes while an order is pending or exposure exists, the frozen `M3_EXEC.metadata_change` requires WAIT/censoring, with no inferred amendment or exit. Registration could only lock a future window with these controls preregistered; it cannot declare its future filter history verified in advance. The current artifacts appropriately authorize no strategy decisions.

Grid validation remains narrower than exchange execution. A verified tick can support exact-decimal price-grid checks; it cannot prove queue priority, depth, spread, partial fills, latency, intrabar ordering, or actual stop fills. The frozen model's limit-touch and OHLC assumptions remain modeled assumptions. The historical metadata STOP and zero historical verified tick coverage stay unchanged; no 2026 receipt can backdate a 2022–2025 epoch.

**Disposition:** protocol semantics are appropriately fail-closed for the captured 403 evidence. Metadata capture remains unresolved for both symbols, so prospective readiness and OOS registration cannot be promoted on this evidence. `trade_entry_allowed=false`; PAPER and LIVE stay off.
