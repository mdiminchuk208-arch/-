## Access and identity

The official `api.bybit.com` V5 instruments, current/old M15, orderbook, funding history and OI requests for both requested `BTCUSDT` and `ETHUSDT` returned HTTP 403, with the same literal body: `error:The Amazon CloudFront distribution is configured to block access from your country` [bybit:BTCUSDT_instrument] [bybit:ETHUSDT_instrument] [bybit:BTCUSDT_m15now] [bybit:ETHUSDT_m15now] [bybit:BTCUSDT_m15old] [bybit:ETHUSDT_m15old] [bybit:BTCUSDT_book1] [bybit:ETHUSDT_book1] [bybit:BTCUSDT_funding] [bybit:ETHUSDT_funding] [bybit:BTCUSDT_oi] [bybit:ETHUSDT_oi]. Official integration guidance explicitly warns: “IP addresses located in the US or Mainland China are restricted and will return a 403 Forbidden error for requests to Bybit API” [bybit:bybit_docs_guide]. The observed cloud response establishes restriction, without identifying the proxy's actual location. We stopped after the bounded requested probes. The ordinary GitHub CI probe is a separate root task.

The official instruments schema describes online USDT contract metadata including `priceFilter.tickSize`, `lotSizeFilter.qtyStep`, `settleCoin` and `fundingInterval` [bybit:bybit_docs_instrument]. No live response established the current identity or filters of either requested symbol. The Kline docs list interval `15` and start/end pagination [bybit:bybit_docs_kline], but no current or 2024-10-13 old M15 bar was retrieved. Public orderbook docs describe the V5 depth endpoint [bybit:bybit_docs_orderbook], but no valid snapshot or normalized book exists. Funding history docs say intervals vary by symbol and point to instruments-info for the interval [bybit:bybit_docs_funding]. OI history is documented [bybit:bybit_docs_oi]. These are capability descriptions, not current product, historical continuity or accessibility proof. Current tick epochs and causal capture from this cloud remain unresolved.

## Fees and bot controls

The current official fee page says “Last updated on 2026-09-02” and its `VIP 0` row under “Perpetual & Futures Contracts Trading” states taker `0.0550%` and maker `0.0200%` [bybit:bybit_docs_fee]. These are entered as ordinary base-tier rates, 0.00055 and 0.0002 as decimal fractions. VIP/Pro/Market Maker reductions are separate, and an individual API account's effective rate or exception remains unverified. The same page says funding fees received or paid do not count toward trading volume, consistent with keeping funding separate from the trading-fee matrix [bybit:bybit_docs_fee].

Official V5 order creation docs explicitly cover USDT perpetuals, `reduceOnly`, customizable `orderLinkId`, and TP/SL parameters [bybit:bybit_docs_order]. `Set Trading Stop` creates exchange-side TP/SL conditional orders [bybit:bybit_docs_trading_stop]. Leverage and isolated-margin behavior are described in the position controls [bybit:bybit_docs_leverage]. Order state, position state and private WebSocket order updates are documented [bybit:bybit_docs_realtime_order] [bybit:bybit_docs_position] [bybit:bybit_docs_ws_order]. Exact duplicate-request/idempotency behavior remains to verify. API-key info separates `ContractTrade` permission (`Order`, `Position`) from `Wallet` permission (`Withdraw`) and exposes bound `ips`, supporting Read+Trade without Withdraw at schema level [bybit:bybit_docs_apikey_info]. Rate limits and headers are documented [bybit:bybit_docs_rate_limit]; demo and testnet are documented [bybit:bybit_docs_demo] [bybit:bybit_docs_api_key_final]. These documentation claims do not remove the current cloud API access blocker or establish a working execution location. No status/maintenance feed was verified.

Bybit currently lacks live BTC/ETH instrument filters, old M15 proof, usable books and a functioning API path in this cloud. Its ordinary fee table alone cannot satisfy the research or future-execution hard gates here. No strategy signal, order, account, P&L or private credential was touched.
