# Gate public evidence, 2026-10-12 to 2026-10-13 UTC

All IDs resolve through `SOURCE_INDEX.json` to official URLs, UTC requests, status, filtered response headers, raw paths, and SHA-256. `gate_docs_zip` is Gate's official API v4 Markdown ZIP; all documentation quotations below are from `gate-api-v4-markdown/en/gate-api-v4.md` within that retained archive. `FACTS.json` contains machine-readable findings and all four normalized book observations. Only public GET endpoints were called; no account, fee, order, or private operation was invoked.

## Product, contract units, fees

`gate_btc_contract` and `gate_eth_contract` identify `BTC_USDT` and `ETH_USDT` under `/futures/usdt`, both `type=direct`, trading. Official `Contract` schema (`gate_docs_zip`) says “direct - direct contract” and “The contract multiplier indicates how many units of the underlying asset the face value of one contract represents.” BTC `quanto_multiplier=0.0001`, ETH `0.01`. Book level `s` is contract count; `base quantity = s × quanto_multiplier`. The API contract fields identify `order_price_round=0.1` BTC and `0.01` ETH; the schema calls this “Minimum order price increment.” BTC has `enable_decimal=false`, `order_size_min=1`; ETH has `enable_decimal=true`, `order_size_min=0`, so ETH size granularity needs further exact string validation. Current `config_change_time` fields exist but do not reconstruct historical tick or multiplier epochs.

Both public contract responses contain `maker_fee_rate=-0.0001` and `taker_fee_rate=0.00075`. The official schema describes these as “Maker fee rate, negative values indicate rebates” and “Taker fee rate.” However, Gate documents an authenticated `GET /futures/{settle}/fee` for futures market trading fee rates. The public contract fields alone do not prove the **ordinary base-tier account/API** rates or whether there are account-specific overrides. `gate_fee_schedule` is a dynamic public fee page whose captured HTML did not expose a usable base-tier API table. `gate_docs_fee` resolved to an unrelated listing notice and supplies no fee evidence. Accordingly `FACTS.json.fees.maker_rate` and `.taker_rate` are null; the raw market fields are reported separately. Do not score an account base fee from the public contract fields.

## Data and funding

Gate API docs (`gate_docs_zip`) say futures candlesticks have a maximum 2,000 points per query, with `from`/`to` in Unix seconds and `interval=15m`. They also document `mark_` and `index_` contract prefixes plus a premium-index candle endpoint. Current BTC/ETH native M15 probes succeeded (`gate_btc_m15_now`, `gate_eth_m15_now`). The 2024-10-13 M15 requests (`gate_btc_m15_old`, `gate_eth_m15_old`) returned HTTP 400 with exact message: “Candlestick too long ago. Maximum 10000 points recently are allowed.” No official old native M15 archive was retrieved. This blocks a 2-year public M15 path; pagination within the recent window cannot repair it.

Live contracts report `funding_interval=28800` seconds, i.e. 8 hours. `gate_btc_funding`/`gate_eth_funding` retrieved recent historical rows; old 2024 funding requests returned HTTP 400: “from time exceeds 180-day limit.” Current BTC/ETH `contract_stats` returned `open_interest` and `open_interest_usd` (`gate_btc_oi`, `gate_eth_oi`). Formula, sign convention, platform surcharge, historical OI depth, and full funding continuity remain unverified. The API docs specify public historical funding, premium-index candles, market trades, and order books; endpoint availability alone does not prove deep history.

## Books, order controls, and security

`gate_btc_book_1`, `gate_eth_book_1` (2026-10-12 20:21 UTC) and `gate_btc_book_2`, `gate_eth_book_2` (2026-10-13 06:26 UTC) each have 100 bid and 100 ask levels. Every level is retained in `BOOKS_NORMALIZED.json` and `FACTS.json.books` with exact decimal price/base quantity, exchange timestamp, and source ID. The docs state order-book `interval=0` means unmerged depth and default is 0. These two samples are only contemporaneous diagnostics.

The official API ZIP documents REST and futures WebSocket, query orders/fills/positions, API HMAC SHA-512 signing, and a TestNet base URL. Its leverage endpoint states “leverage ≠ 0: Isolated Margin Mode” and `leverage=0` chooses cross mode. Futures order schema says reduce_only true makes a reduce-only order, offers `tpsl_tp_trigger_price` and `tpsl_sl_trigger_price`, and order `text` custom IDs prefixed `t-` with a 28-byte suffix limit. It also documents futures price-triggered orders and `pos_margin_mode` isolated/cross. Exact duplicate-ID idempotency is unverified; docs warn custom IDs can only query pending orders in one list API.

The API docs state keys can have multiple category permissions (including futures read/write), expose an IP whitelist field, and distinguish wallet/withdrawal operations from futures trading; this supports configuring a futures trade key without wallet permission. The API key/account configuration was not privately tested. Gate documents `X-Gate-RateLimit-*` headers, observed on our public probes, and 100 requests/s for futures order endpoints, subject to endpoint/account rules. `gate_status` retains the public announcements page, though a machine-readable maintenance status feed remains unverified. No GitHub-hosted CI probe was run by this worker.
