# BloFin: public evidence, 2026-10-13 UTC

Raw bytes, request times, HTTP status, filtered headers, and SHA-256 are in `SOURCE_INDEX.json`. All probes used the inherited cloud HTTPS proxy and normal TLS verification. Earlier guessed `history-candles` and `history-funding-rate` paths returned HTTP 200 with JSON `code=404`; corrected documented paths are retained alongside them.

The live linear USDT-settled `SWAP` products are `BTC-USDT` and `ETH-USDT`. Public instruments give `contractValue=0.001 BTC` and `0.01 ETH`, with ticks `0.1` and `0.01` USDT and lot increments of `0.1` contract. Official docs say book quantity is “number of contracts” and that instrument `contractValue` is base units per contract. `bf_instruments`, `bf_api_docs`. Books were captured twice per symbol at distinct exchange times. `FACTS.json` converts every retained level exactly to base quantity using decimal arithmetic. `bf_*_book_1/2`.

The current official Futures fee table shows the Regular tier at `0.0200%` maker and `0.0600%` taker. It separately marks VIP 4 and VIP 5 thresholds for “Non-API Trading”; there is no Regular API exception in the captured table. The account-specific tier and any promotions remain unverified. `bf_fee_page`. Funding is separate from trading fees; current responses show 8-hour intervals for both and the documented public history endpoint returned records. The formula/sign of a funding transfer was not established here. `bf_*_funding_current`, `bf_*_funding_history_v2`, `bf_api_docs`.

Current native 15-minute candles and **closed** candles at `2024-10-13T00:00Z` were retrieved for both symbols. The docs define `ts` as opening time, `confirm=1` as complete, and `after` as paging toward earlier records (up to 1,440 per call). The old samples prove point retrieval, not continuous two-year coverage. Public recent trades and current OI were obtained; index and mark-price candle endpoints are documented and BTC current samples were obtained. Historical order books, historical OI, and live-symbol filter epochs remain unproven. `bf_api_docs`, `bf_*_m15_now`, `bf_*_m15_old_direct`, `bf_*_trades`, `bf_*_oi`, `bf_btc_index_now`, `bf_btc_mark_now`.

Official docs provide isolated margin and leverage controls, `reduceOnly`, TP/SL trigger orders, client IDs and order-detail lookup by client ID, REST plus public/private WebSocket, HMAC signing, and a demo API. They explicitly state `reduceOnly` is ignored in hedge mode, so one-way mode is required for that control. API-key permissions are listed separately as READ, TRADE and TRANSFER; TRADE allows placing/canceling orders, while TRANSFER is a separate permission. Up to 20 IPs can be bound, and an unbound key expires after 90 days. `bf_api_docs`. No authenticated API call or order was made.

Remaining limits: historical live tick epochs, historical book/OI depth, a public status feed, and actual user-account/jurisdiction applicability are unverified. These observations support a venue comparison; they do not establish executable historical metadata or future fill quality.
