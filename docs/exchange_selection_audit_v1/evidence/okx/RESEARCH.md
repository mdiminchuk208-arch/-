# OKX venue evidence

Captured from the managed cloud environment on 2026-10-12 and 2026-10-13 UTC through its inherited HTTPS proxy and CA. All source IDs below resolve to `SOURCE_INDEX.json`, which records the official URL, HTTP status, request/retrieval times, raw body SHA-256, and receipt path. The large official API documentation body is `docs_main`; references with `#` identify its section anchor. No account, private API, order, or VPN was used.

## Product and current filters

`instrument_btc` and `instrument_eth` returned `BTC-USDT-SWAP` and `ETH-USDT-SWAP` with `instType=SWAP`, `ctType=linear`, `settleCcy=USDT`, and `state=live`. BTC has `ctVal=0.01`, `ctValCcy=BTC`, `ctMult=1`, `tickSz=0.1`, `lotSz=0.01`, and `minSz=0.01`. ETH has `ctVal=0.1`, `ctValCcy=ETH`, `ctMult=1`, `tickSz=0.01`, `lotSz=0.01`, and `minSz=0.01`. The official `docs_main#public-data-rest-api-get-instruments` says `SWAP: Perpetual Futures` and describes `ctVal` as the face value in base currency for linear contracts. These filters are current observations; no historical tick epoch was recovered.

## Native history and auxiliary data

`m15_btc_old_after` and `m15_eth_old_after` each returned a native `15m` candle opening at `2024-10-13T00:00:00Z`, with `confirm=1`. Recent `15m` rows succeeded in `m15_btc_now` and `m15_eth_now`. `docs_main#order-book-trading-market-data-get-candlesticks-history` states that `after` requests earlier records, `before` newer records, and `confirm=1` means completed. An actual two-year sentinel establishes point reachability for both products; it does not establish every intervening bar, missing-bar semantics, or immutable historical tick filters. The separate `m15_*_old_before` probes returned the latest rows, consistent with the documented standalone `before` behavior.

The public history-trades endpoint returned BTC and ETH rows (`trades_history_btc`, `trades_history_eth`); official docs limit recent transaction history to three months (`docs_main#order-book-trading-market-data-get-trades-history`). BTC mark and index `15m` history returned rows (`mark_history_btc`, `index_history_btc`); ETH was not probed for those series. BTC/ETH `15m` open-interest history returned rows (`oi_history_btc`, `oi_history_eth`), while both 2024 `end` sentinels returned empty data (`oi_history_old_btc`, `oi_history_old_eth`). Official docs say this endpoint retrieves the latest 1,440 entries (`docs_main#trading-statistics-rest-api-get-contract-open-interest-history`). No historical order-book archive or full instrument-change epoch series was established.

## Books and exact units

Two 400-level books per side and symbol were captured around `2026-10-12T20:21Z` and `2026-10-13T06:26Z` (`book_btc_1`, `book_btc_2`, `book_eth_1`, `book_eth_2`). Official `docs_main#order-book-trading-market-data-get-order-book` says the book quantity is the number of contracts for derivatives. `BOOKS_NORMALIZED.json` preserves every row's raw contracts and decimal base quantity; `FACTS.json.books` presents `[price, base_qty]` rows for scoring. Because the two observed linear contracts have `ctMult=1`, `base_qty = contracts × ctVal`: for example, BTC sample 1 best ask `537.12` contracts equals `5.3712 BTC`. These snapshots are limited contemporaneous observations, not future fill guarantees.

## Fees and funding

**Current ordinary API perpetual fee remains unresolved.** The official `fee_help_en` page uses the literal illustrative phrase `Trader A (Maker fee: 0.02%; Taker fee: 0.05%)`. It does not establish today's base-tier rate for this account/API product. The captured `fee_page_en` response exposes a server-rendered `Spot` fee tab, not a verified SWAP table. `docs_main#trading-account-rest-api-get-fee-rates` specifies `GET /api/v5/account/trade-fee`, a private account endpoint, and notes that a negative rate is commission; it was not called. `docs_main#public-data-rest-api-get-instruments` further says instrument fee group and fee-rate endpoint should be used together for a symbol's rate. Maker/taker remain `null` in `FACTS.json`; no illustrative, VIP, or promotional rate was substituted.

`funding_btc` and `funding_eth` show live `fundingTime`/`nextFundingTime` eight hours apart and `formulaType=withRate`, but the official docs warn that interval can change by contract (`docs_main#public-data-rest-api-get-funding-rate`). They state positive projected funding means longs pay shorts and negative means shorts pay longs. `funding_history_btc` and `funding_history_eth` returned current rows; `docs_main#public-data-rest-api-get-funding-rate-history` limits history to up to three months. A platform surcharge and full older funding series remain unknown. Funding is separate from trading commission.

## Bot controls and operational access

Official `docs_main` documents REST orders, order/position queries, WebSocket order/fills/instrument channels, isolated SWAP margin and leverage, `reduceOnly` for FUTURES/SWAP net mode, attached TP/SL and algo orders, and `clOrdId`. `docs_main#order-book-trading-algo-trading-post-place-algo-order` warns that a net conditional order carrying both TP and SL executes stop-loss logic only; integration must use supported combinations. `clOrdId` uniqueness is described for currently pending orders, so durable idempotency is not assumed. The API-key section distinguishes Trade from Withdraw and recommends IP binding (`docs_main#overview-api-key-creation-api-key-permissions`, `docs_main#overview-api-key-creation-api-key-security`). Per-endpoint rate limits are documented. `system_status` and `server_time` returned HTTP 200 and API code `0`; the status response had an empty data list. These are public/documented checks, not proof that an account can safely trade or is jurisdictionally eligible.

Current blockers for primary execution consideration are a verified ordinary API SWAP fee, account-applicable protective order/margin behavior, and account/jurisdiction eligibility. For research, BTC/ETH native two-year sentinel and current filters are evidenced, while intervening history continuity and historical tick epochs remain unresolved.
