In the frozen audit builder's Kraken CI normalization branch, `stamp` remains unset and `time_utc` therefore uses the receipt's `response_completed_at`. The raw public response also retains an ISO-UTC `serverTime`, which should be modeled separately. For example, exchange time `2026-10-13T06:39:00.732Z` and receipt completion `2026-10-13T06:39:00.860645+00:00` are distinct. Thus **the four Kraken CI normalized `time_utc` fields denote receipt completion, not exchange event/server time**. Their original server times remain available in hash-verified raw responses. Local Kraken normalized books use exchange server time. Consumers must not silently treat the two timestamp kinds as identical.

All four CI observations remain separately retained, and exact duplicate suppression does not remove or introduce an observation as a result.
