# OKX Stage A cost and funding archive follow-up

As of 2026-10-13 18:13 UTC, **the historical funding-rate input path is recovered for the development window**, while **ordinary API SWAP fee applicability remains unresolved**. This document records input data only. It contains no v3 trade outcomes and does not authorize Stage B. It supersedes the funding-availability blocker in the earlier [cost/funding readiness note](COST_FUNDING_READINESS.md), but does not revise that note's fee finding.

The official [OKX historical-data page](evidence/cost_funding/okx_historical_data_en.receipt.json) advertises perpetual funding archives since March 2022. Its [page application](evidence/cost_funding/okx_historical_data_app_js.receipt.json) uses public `POST /priapi/v5/broker/public/trade-data/download-link` with `module="3"`, `instType="SWAP"`, `instFamilyList=["BTC-USDT","ETH-USDT"]`, and monthly date ranges in UTC milliseconds. No cookies, authentication, account API, trading API, or automatic redirects were used. The service enforces a six-month query span: the [full-range attempt](evidence/cost_funding/archive_funding_full_index.receipt.json) returned code `50077`; four shorter, successful indices cover October 2024–September 2026 ([first](evidence/cost_funding/archive_funding_index_2024_10_2025_03.receipt.json), [second](evidence/cost_funding/archive_funding_index_2025_04_2025_09_retry1.receipt.json), [third](evidence/cost_funding/archive_funding_index_2025_10_2026_03_retry1.receipt.json), [fourth](evidence/cost_funding/archive_funding_index_2026_04_2026_09.receipt.json)). Two initial middle-range attempts returned 429/code `50011`; successful retries and failed receipts were both retained. October 2026 has no completed monthly archive entry yet ([index](evidence/cost_funding/archive_funding_index_2026_10.receipt.json)).

All **48** indexed monthly BTC/ETH ZIPs were downloaded from the returned OKX CDN URLs, with individual URL, UTC, HTTP status, byte count, and SHA-256 receipts in [cost/funding evidence](evidence/cost_funding/). Each ZIP contains one CSV with `instrument_name,funding_rate,funding_time`. A strict [archive audit](evidence/cost_funding/FUNDING_ARCHIVE_AUDIT.json) verified every receipt hash, exact contract name, parseable signed decimal rate, increasing unique UTC millisecond timestamps, all 24 expected archive file months per symbol, and ZIP/CSV integrity. OKX groups each file's first UTC settlement in the previous UTC calendar month; every row maps to its filename month after adding eight hours. That observed grouping is a file partition convention, not an assumed change in funding timestamps.

Each contract has **2,190 archive rows** with consecutive 8-hour timestamps. Bounded official public [BTC](evidence/cost_funding/funding_recent_btc_limit100.receipt.json) and [ETH](evidence/cost_funding/funding_recent_eth_limit100.receipt.json) funding-history GETs supplied the incomplete October 2026 tail. For each contract, **60 overlapping timestamps** matched the archive rate exactly against API `realizedRate`; there were zero mismatches. The API adds 40 settlements after the last archive row, through **2026-10-13 16:00 UTC**. From **2024-10-13 00:00 UTC through 2026-10-13 16:00 UTC**, the wider merged input has **2,193 rows per contract**, zero duplicate timestamps, and every adjacent gap exactly eight hours. The [BTC merged CSV](evidence/cost_funding/BTC_USDT_SWAP_funding_development_20241013_20261013.csv) and [ETH merged CSV](evidence/cost_funding/ETH_USDT_SWAP_funding_development_20241013_20261013.csv) retain the source body for each row; their hashes and month-level counts are in the audit.

The subsequently committed Stage A preregistration fixes the development end at **2026-10-13 00:00 UTC exclusive**. Accordingly, the exact scoped inputs are [BTC prereg CSV](evidence/cost_funding/BTC_USDT_SWAP_funding_development_prereg_20241013_20261013exclusive.csv) and [ETH prereg CSV](evidence/cost_funding/ETH_USDT_SWAP_funding_development_prereg_20241013_20261013exclusive.csv): **2,190 rows each**, from **2024-10-13 00:00 UTC** through **2026-10-12 16:00 UTC**, every adjacent gap eight hours, no duplicate timestamp, exact symbol identity. The [audit JSON](evidence/cost_funding/FUNDING_ARCHIVE_AUDIT.json) records both scoped SHA-256 hashes. The extra October 13 rows in the wider captures are outside the preregistered development window and must not enter the qualification run. Funding during the 2023-10-14 warmup is inapplicable because no positions are open then.

These observations support using the **actual signed historical rates and settlement timestamps** for a frozen funding-cost rule. They do not prove future schedules or a universal 8-hour rule. Funding cash also needs a preregistered, causal position-at-settlement rule and valuation/notional convention, with a documented price source; rate history alone does not complete net-cost accounting. Preserve the official sign rule: positive rates charge longs and credit shorts; negative rates do the reverse. Do not apply a current rate or current min/max cap backward. Define the treatment of any position exactly on a settlement boundary before outcomes.

For fees, the [public fee-page application](evidence/cost_funding/okx_fees_logic_js.receipt.json) calls `/v3/users/support/common/fee/display-config`; an unauthenticated [public GET](evidence/cost_funding/okx_fee_display_config_public.receipt.json) returned only Spot tables for this locale. It yields no ordinary SWAP maker/taker rate. The retained FAQ's 2/5 bp figures remain illustrative, and the frozen 6 bp/side fee remains a model assumption, not historical fee evidence. Stage A still needs an explicit conservative, preregistered fee compatibility policy or applicable official evidence before financial execution.
