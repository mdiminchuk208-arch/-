# OKX Stage A cost and funding readiness

Status: **OPEN / conditional STOP** as of 2026-10-13 UTC. This is a pre-outcome evidence audit. It contains no v3 trade outcomes and does not alter the frozen strategy or authorize Stage B.

## Fee evidence and model distinction

- The frozen v3 model charges **0.0006 (6 bp) per side in fees** and **0.0002 (2 bp) per side in slippage**, with funding `null` ([frozen specification](../machine_strategy_v3_design/MACHINE_STRATEGY_V3_SPEC.md)). For equal entry/exit notional, the modeled round trip is approximately **12 bp fees + 4 bp slippage = 16 bp**. These are existing model parameters, **not** verified OKX historical or account-applicable rates.
- The retained official OKX FAQ gives an illustrative “Trader A (Maker fee: 0.02%; Taker fee: 0.05%)”. The retained public fee page exposes a Spot tab. Neither establishes the ordinary API fee for `BTC-USDT-SWAP` and `ETH-USDT-SWAP`. OKX's API documentation points to private `GET /api/v5/account/trade-fee` together with the instrument fee group for the symbol. No private endpoint was used ([OKX research](../exchange_selection_audit_v1/evidence/okx/RESEARCH.md), [source index](../exchange_selection_audit_v1/evidence/okx/SOURCE_INDEX.json), [checkpoint](../exchange_selection_checkpoints_v1/okx.json)). A present-day rate also cannot be silently assigned to 2024–2026 historical fills.
- For a linear position of base quantity `q`, entry price `E`, and exit price `X`, modeled commission is `q(f_e E + f_x X)` USDT; modeled slippage has the same form with `s_e,s_x`. Divide by the frozen positive cash-risk denominator to express a cost in R. Funding is a separate signed cash flow at each settlement while the position is open. A maker discount is inappropriate unless fill evidence and the frozen fill rule support maker execution; otherwise all legs should be treated as taker for the cost policy.

**Defensible preregistration choices before any outcomes:** (1) obtain official, account-applicable ordinary API SWAP fee evidence and declare a period-aware or deliberately adverse all-taker fee schedule, including a rule for unknown historical fee epochs; or (2) retain 6 bp/leg as an explicitly hypothetical policy floor and require a prespecified higher-cost sensitivity plus a STOP if subsequently verified applicable costs exceed the policy envelope. Choice (2) does **not** establish an exchange-backed upper bound or, by itself, clear Stage A. Never use the FAQ's 2/5 bp example, the Spot SSR table, VIP/rebate/promotional pricing, or the current fee endpoint as historical fee proof. The numeric stress envelope, pass criterion, and action on breach must be frozen by the qualification owner before outcome access; this audit does not set strategy thresholds.

## Historical funding path

- Retained official API documentation states `GET /api/v5/public/funding-rate-history` returns up to **three months**, with `realizedRate` the actual funding rate. Retained recent BTC/ETH samples returned rows. Two new public GET probes with `after=1728777600000` (2024-10-13 00:00 UTC) and `limit=2` returned HTTP 200, API code `0`, and empty `data` for both contracts. Thus this API cannot supply the full warmup/development interval through the tested pagination path. See [BTC receipt](evidence/cost_funding/funding_btc_2024_after.receipt.json) and [ETH receipt](evidence/cost_funding/funding_eth_2024_after.receipt.json), with the adjacent raw bodies.
- A newly captured [official OKX historical-data page](evidence/cost_funding/okx_historical_data_en.receipt.json) says “Historical perpetual funding rates from March 2022 onwards”, which nominally covers the 2023-10-14 warmup and 2024-10-13 through 2026-10-13 development period. Its [official page application](evidence/cost_funding/okx_historical_data_app_js.receipt.json) maps funding to module `3`, supports `SWAP`, and requests download links through `/priapi/v5/broker/public/trade-data/download-link` via **POST**. A bounded official public [GET of its SWAP instrument families](evidence/cost_funding/okx_archive_swap_instruments.receipt.json) returned API code `0` and included `BTC-USDT` and `ETH-USDT`. This establishes an official archive lead, **not** that the exact monthly files are publicly downloadable, complete, or contract-specific. No POST, login, private account call, download, or non-OKX source was used in this audit.
- The archive path needs a separate allowed collection step: obtain exact BTC/ETH `SWAP` funding files for every relevant month, preserve each URL/UTC/status/hash and raw bytes, verify symbol and UTC settlement timestamps, duplicate/missing rows, source sign and actual-versus-projected field, and reconcile overlapping recent rows against the public API. Record actual funding intervals and any formula/cap changes by their valid dates. The current 8-hour intervals or current `minFundingRate`/`maxFundingRate` fields are not historical caps.

If full official funding provenance remains unavailable, the conservative rule is **STOP for historical net-cost qualification whenever an allowed holding can cross a funding settlement**. Charging zero, always taking a favorable sign, copying current rates backward, or assuming a fixed interval or unverified bound cannot clear that gate. A truly funding-free rule would require a pre-outcome, causally enforceable flat-position schedule and would change the validated trade universe; it needs a separately frozen compatibility version. The existing v3 funding field is `null`, so no complete funding-inclusive net result can be asserted from the frozen cost model alone.

All new receipts and raw bodies are under [cost/funding evidence](evidence/cost_funding/). Fetches used the inherited managed HTTPS proxy and CA verification, with no automatic redirect following. The initial generic `/historical-data` request returned a 302; its explicit `/en-us/historical-data` target returned 200. The generic `/data-download` path and its explicit `/en-us` target returned 404 and are retained only as negative route probes.
