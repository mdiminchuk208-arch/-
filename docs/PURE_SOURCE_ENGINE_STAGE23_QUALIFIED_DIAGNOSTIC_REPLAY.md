All new infrastructure is TECHNICAL_NORMALIZATION. No SOURCE rule, numeric quality proxy, PROJECT overlay or financial permission is added. Frozen Stage1–22 files and artifacts remain unchanged.

## Explicit inputs and availability

`AnnotationDelivery` contains declared arrival time, immutable Stage18 claim and immutable witness bytes. Claim known time cannot follow declared arrival; the artifact SHA must match. The catalog must retain false trade/financial/proxy permissions and no project policies.

`EqualPairRequest` and `SfpContextRequest` identify explicit candidates, their exact observation windows and first request time. Windows are already closed. Requests do not rank candidates or establish that they are source-valid. No annotations or candidate winners are generated by the provider.

`QualifiedDiagnosticProvider` runs through the existing Stage10 closed-data replay runner and Stage11 canonical object producer. It advances the Stage20 journal on every frame, including frames without annotation arrivals. Deliveries are consumed only at the first actual closed decision at/after their declared arrival, then bound to that actual prefix and parent batch. Off-grid arrival rounds forward, never backward. Future requests and deliveries are unavailable to earlier consumers.

The provider calls Stage21/22 qualified consumers internally and returns their complete typed envelopes, original witness receipts and actual requests alongside canonical object diagnostics. It emits no setup or execution assessments. No context or pair PASS creates a trade, READY or permission to enter.

## Replay identity and failure behavior

The canonical batch fingerprint includes inherited object diagnostics, available annotation receipts, request identities and qualified consumer results. Delivery/claim/request timestamps are normalized to UTC at the new Stage23 boundary. Equivalent instants cannot change fingerprints or evade duplicate requests. Schedules are immutable and sorted canonically; input order does not select an author, branch or pair. Full input SHA covers catalog, market, complete request schedule and delivery claim/witness identities. This SHA is run-level audit metadata only: including a future schedule hash in each decision would itself contaminate prefix equality, so it is deliberately absent from per-step evidence.

Prefix equality is verified on actual per-step data/evidence/runtime receipts. Full-run input identity separately changes if future schedules change. Neither a future annotation's content nor a future request ID can change earlier decision receipts.

A session requires a strictly advancing replay clock; exact repeat uses a fresh provider. Per-claim ingestion remains atomic. If any input or consumer fails within a multi-input frame, no incomplete batch is emitted and the provider is poisoned for further use. Previously completed batches remain immutable diagnostics; resumption of that failed instance is forbidden.

## Trust boundaries

Declared schedules are dataset inputs, not authenticated evidence of real-world arrival. The caller must preserve causal arrival records and supply qualified SOURCE annotations. Hashes establish content integrity and binding, not human identity, annotation truth or historical blindness. Stage23 does not create a durable annotation service or prove supplied market labels. Synthetic test fixtures are explicitly not SOURCE-valid market trade cases.

EQH/EQL consumer facts are object qualifications only. SFP liquidity context remains TRADE_CONTEXT; full Methodichka pattern status stays UNKNOWN. Old SW8 next-open transport is not silently promoted to every priority1 SFP. Existing setup/execution/re-entry behavior and all financial/trading permissions remain frozen.
