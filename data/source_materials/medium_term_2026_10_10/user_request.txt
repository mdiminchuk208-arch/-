Продолжай работу над проектом Crypto Bot Strategy Engine с текущего состояния проекта. Не начинай стратегию заново и не меняй её концепцию без необходимости.

Главная задача: исправить торговый горизонт стратегии. Предыдущие прогоны дали около 16 000 сделок, что указывает на слишком короткий intraday / фактически скальпинговый режим. Изначальная концепция проекта — СРЕДНЕСРОЧНАЯ торговля, а не скальпинг.

ВАЖНО:
- Не считать предыдущий backtest окончательной оценкой стратегии.
- Не выбрасывать текущую стратегию.
- Не включать LIVE trading.
- `trade_entry_allowed=false` должен остаться.
- Не менять safety-инварианты.
- Не подгонять стратегию специально под прибыльный результат.
- Не ставить фиксированные TP +3%, +5%, +8%. Эти проценты приводились только как пример того, что среднесрочное движение должно быть существенно больше комиссий и slippage.

Нужно сделать следующее.

1. ПРОВЕРИТЬ ТЕКУЩУЮ РЕАЛИЗАЦИЮ НА СКАЛЬПИНГОВЫЕ ДОПУЩЕНИЯ

Проведи аудит Strategy Engine и backtest-логики и найди всё, что может искусственно создавать слишком короткие сделки или слишком большое количество входов.

Проверить минимум:
- используемые таймфреймы;
- основной timeframe формирования setup;
- timeframe market context;
- entry timeframe;
- `max holding bars`;
- любые time-based exit;
- forced exit;
- timeout сделки;
- expiry setup;
- слишком быстрое инвалидирование;
- слишком частые повторные входы;
- re-entry после SL;
- повторный вход в один и тот же setup;
- cooldown;
- сигнал на каждой новой свече;
- duplicate signals;
- возможность открыть несколько почти одинаковых setup подряд;
- чрезмерно короткие confirmation windows;
- ATR-based TP/SL;
- FTA;
- TP1/TP2/TP3;
- BOS / CHOCH invalidation;
- order block lifetime;
- FVG / imbalance logic;
- liquidity logic;
- OTE;
- premium/discount;
- любые настройки, рассчитанные на микродвижения.

Сначала составь технический вывод, почему предыдущий backtest мог получить примерно 16 000 сделок.

2. ВЕРНУТЬ СТРАТЕГИЮ В СРЕДНЕСРОЧНЫЙ РЕЖИМ

Целевая архитектура таймфреймов:

- D1 / H4 — старший market context, trend, range, premium/discount, major liquidity.
- H4 / H1 — основной setup и подтверждение идеи сделки.
- Более низкие timeframe использовать только при необходимости для уточнения точки входа, но они НЕ должны самостоятельно генерировать отдельную скальпинговую торговую идею.

Главный принцип:

низкий TF = execution refinement,
а не отдельная стратегия.

Сделки должны преимущественно жить ЧАСЫ / ДНИ, а не минуты.

Не вводи искусственное правило вида «каждая сделка должна держаться минимум N часов». Сделка может быстро закрыться, если:
- достигнут TP;
- сработал SL;
- произошла структурная invalidation;
- рынок сделал необходимое движение быстрее обычного.

Но сама стратегия не должна быть построена вокруг постоянных коротких движений.

3. УБРАТЬ ЧРЕЗМЕРНУЮ ЧАСТОТУ ТОРГОВЛИ

Проверь и исправь:
- повторные сигналы внутри одного setup;
- повторный вход после микровыбивания;
- повторное использование одного POI без нового причинного подтверждения;
- слишком быстрый re-entry;
- отсутствие lifecycle у setup;
- отсутствие cooldown;
- дублирование одного сигнала на нескольких близких timeframe;
- генерацию нескольких сделок по фактически одной торговой идее.

Один setup должен иметь понятный lifecycle:

DISCOVERED
→ QUALIFIED
→ READY
→ ENTERED
→ CLOSED / INVALIDATED / EXPIRED

После завершения setup нельзя бесконечно перегенерировать тот же вход без нового структурного основания.

4. НЕ ИСПОРТИТЬ SOURCE-ALIGNED ЛОГИКУ

Продолжать соблюдать уже принятую methodology/source-alignment.

В частности:
- ORDER_BLOCK повторно используется только если есть независимо подтверждённая causal reaction на младшем TF.
- DEMAND / SUPPLY должны оставаться fresh / untested.
- Premium/Discount должен использоваться корректно относительно актуального dealing range.
- BOS / CHOCH / liquidity / FVG / IMB / OTE / FTA должны использоваться причинно, а не как набор независимых галочек.

Не упрощай стратегию ради уменьшения количества сделок.

Количество сделок должно уменьшиться естественно из-за правильного среднесрочного контекста и качественной фильтрации.

5. TP / SL

НЕ ставить фиксированные тейки:
- +3%;
- +5%;
- +8%;
или любые другие фиксированные проценты только ради среднесрока.

TP1 / TP2 / TP3 должны по-прежнему определяться через:
- market structure;
- liquidity;
- FTA;
- R:R;
- volatility;
- ATR там, где он методологически оправдан;
- реальные structural targets.

Текущая логика распределения позиции:
- TP1 = 40%;
- TP2 = 30%;
- TP3 = 30%.

После TP1:
- SL переводить в breakeven с учётом fees и slippage, согласно текущим правилам проекта.

Главная идея:
ожидаемое движение сделки должно быть достаточно большим, чтобы комиссии и slippage не уничтожали edge.
